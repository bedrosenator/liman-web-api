# 🔀 Git Workflow & Deployment Rules (Liman Web API)

Все AI-агенты, работающие над проектом **liman-web-api**, обязаны строго соблюдать данный регламент ветвления, код-ревью и деплоя:

---

## 1. Главное правило деплоя
> [!IMPORTANT]
> **ВСЕГДА СОЗДАЕМ PULL REQUEST ПЕРЕД ДЕПЛОЕМ!**
> Прямой пуш в ветку `main`/`master` или деплой непроверенных изменений на сервер без Pull Request **категорически запрещен**.

---

## 2. Порядок работы (Git Flow)

0. **Составление и согласование плана (ОБЯЗАТЕЛЬНО):**
   - **ВСЕГДА СОЗДАЕМ И ОБСУЖДАЕМ ПЛАН ДО НАЧАЛА КОДИРОВАНИЯ!**
   - Перед написанием кода агент исследует контекст, формирует пошаговый план реализации (файлы, контракты, UI, тесты) и представляет его пользователю.
   - Переход к созданию ветки и написанию кода разрешён **только после явного одобрения плана** пользователем.

1. **Создание ветки под задачу:**
   - Каждое изменение, фича или багфикс разрабатывается в отдельной ветке.
   - Именование веток:
     - `feat/<feature-name>` — для новой функциональности (например, `feat/horoshop-brand-currency-export`).
     - `fix/<bug-name>` — для исправления ошибок.
     - `refactor/<scope>` — для рефакторинга.

2. **Локальная верификация:**
   - Перед коммитом и пушем обязателен полный прогон тестов и сборки:
     ```bash
     npm test
     npm run build
     cd client && npm test && npm run build
     ```
   - 0 упавших тестов, 0 ошибок сборки.

3. **Пуш и создание Pull Request:**
   - Запушить ветку в GitHub: `git push -u origin <branch-name>`.
   - Сформировать Pull Request в ветку `main`.
   - Оформить описание PR: перечислить решенные задачи, внесенные изменения и результаты тестов.
   - Предоставить пользователю прямую ссылку на Pull Request.

4. **Код-ревью:**
   - Выполнить самопроверку (code review) созданного PR на соответствие Clean Code Standards, SOLID, DRY, отсутствие хардкода предметной области и безопасность.

5. **Мердж и Деплой:**
   - Деплой на продакшн/стейджинг сервер (`scripts/deploy.sh`) выполняется **только после** создания PR, его проверки и одобрения пользователем (или вливания в `main`).
