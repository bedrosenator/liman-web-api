## 🏗️ Архитектурные предложения и решения

### 1. Подтягивание названия магазина Хорошоп
* **Проблема:** Сейчас в шапке отображается `tenant.name` (`Columb Shop (Локальная MariaDB)`), которое задается при сидировании в `tenant.service.ts`.
* **Решение:**
  - В сущность `Tenant` добавляем опциональное поле `horoshopShopTitle: string`.
  - При успешном подключении к API Хорошоп (`ping` или первый запрос) запрашиваем метаданные магазина / страницы через API Хорошоп или парсим заголовок главной страницы домена магазина, сохраняя официальное имя магазина в `horoshopShopTitle`.
  - В заголовке `ClientPortalPage.tsx` приоритет отображения:
    `tenant.horoshopShopTitle || tenant.horoshopDomain || tenant.name`.

### 2. Прямой экспорт каталога без возни со ссылками на фид
* **Вариант А (Прямой Push через API — Рекомендуемый):**
  - Кнопка в UI: **«Экспорт товаров в Хорошоп»**.
  - Модальное окно с выбором параметров:
    - Режим: Только новые товары / Обновить существующие / Полная перезапись.
    - Что выгружать: Цены, Остатки, Описания, Фотографии, Категории.
  - По нажатию запускается BullMQ-задача `export-liman-to-horoshop`.
  - Воркер порциями по 50-100 товаров отправляет структурированный JSON в эндпоинт Хорошоп `/api/catalog/import/`.
  - В UI отображается прогресс-бар в реальном времени (0-100%) и детальная статистика (создано, обновлено, пропущено, ошибок).
* **Вариант Б (Сохранение фида как альтернативы):**
  - Ссылку на фид оставляем в скрываемом блоке «Для опытных / Дополнительно» на случай, если клиент настроил автоматический парсинг по расписанию внутри самого Хорошопа.

## 📋 План реализации и Выполненные работы

1. **Backend**:
   - Расширен `HoroshopApiClient` методами получения информации о магазине (`getShopInfo`), списка категорий через `/api/pages/export/` (`getCatalogCategories`), и пакетного создания/обновления каталога через `/api/catalog/import/` (`importCatalog`).
   - Создана очередь `export-horoshop-catalog` и процессор BullMQ `HoroshopExportProcessor` с поддержкой режимов `full_overwrite`, `only_new`, `update_existing`, постраничной загрузкой каталога (батчи по 500), нарезкой чанков по 100 товаров и паузой 1500 мс.
   - Добавлены эндпоинты:
     - `POST /api/v1/horoshop/:tenantId/export/catalog` — постановка задачи экспорта;
     - `GET /api/v1/horoshop/:tenantId/export/categories` — получение дерева категорий магазина Хорошоп;
     - `GET /api/v1/sync/jobs/export-horoshop-catalog/:jobId` — опрос статуса и прогресса BullMQ.
   - Атомарное сохранение связей в PostgreSQL `product_mappings`: статус `synced` фиксируется только при коде `0`, ошибки фиксируются в `lastSyncError`.
2. **Frontend**:
   - Создан компонент `HoroshopExportModal.tsx` с выбором режима, переключателями полей, выпадающим списком целевой категории Хорошоп, анимированным прогресс-баром (0–100%) и детальным отчетом.
   - Добавлена кнопка «Прямий експорт» в Action Hub `ClientPortalPage.tsx`.
   - В шапке портала отображается реальное динамическое название магазина (`horoshopShopTitle`).

## 🔍 Инциденты и Решенные Проблемы (Knowledge Base)

### 1. Отсутствие динамического создания категорий в API Хорошоп
- **Симптом:** При выгрузке каталога все позиции отклонялись Хорошопом с ошибкой: `код 7: "Категория ... не найдена, либо в категории указан неверный шаблон"`.
- **Причина:** Эндпоинт Хорошоп `/api/catalog/import/` не создает категории динамически на лету. Каждому товару требуется указать существующую категорию в поле `parent`.
- **Решение:** Реализован метод `HoroshopApiClient.getCatalogCategories`, который извлекает страницы каталога (`parent: 97`) из `/api/pages/export/` и формирует полные пути (`Електроніка/Аксесуари`). В модальное окно добавлен селектор целевой категории по умолчанию (`defaultCategoryPath`), куда автоматически направляются товары без прямого совпадения категорий.

### 2. Предупреждение по штрихкоду и системный атрибут `gtin`
- **Симптом:** Выгрузка завершалась с 10 ошибками из 10, хотя товары были привязаны к категории `Електроніка/Аксесуари`.
- **Причина:** В Хорошоп передавалось поле `barcode`. Однако стандартное поле штрихкода в каталоге Хорошоп называется `gtin`. При передаче `barcode` Хорошоп возвращал неблокирующее предупреждение `код 11: "Параметр barcode не найден"`, одновременно успешно обновляя товар (`код 0: "Товар обновлен"`).
- **Решение:** 
  1. В `HoroshopExportProcessor.buildProductItem` штрихкод сопоставлен со свойством `item.gtin = product.barcode`.
  2. В `HoroshopApiClient.parseHoroshopLogEntry` предупреждения шаблона (`код 11`) больше не трактуются как фатальные ошибки, если в записи присутствует подтверждение успешного создания/обновления (`код 0`).

### 3. Очистка базы данных от фантомных связей
- **Симптом:** Ранее при фиктивных ответах сервиса в `product_mappings` ошибочно сохранялся статус `synced` для невыгруженных товаров.
- **Решение:** Выполнен сброс фантомных записей в статус `error`, гарантируя повторную отправку при последующих экспортах.
