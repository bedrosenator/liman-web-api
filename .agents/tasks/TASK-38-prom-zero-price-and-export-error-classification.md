## 🎯 Цели задачи

1. **Исключение ошибок `price: Укажите значение от 0.01 до 99999999999999` в Prom API**:
   - При экспорте (`PromExportProcessor`) и синхронизации цен (`PromSyncService`) не передавать поле `price`, если `product.price <= 0` или цена не заполнена (в `POST /products/edit_by_external_id` поле `price` опционально).
   - При отсутствии валидной цены гарантированно выставлять статус наличия `presence: 'not_available'`, чтобы товар не был доступен для заказа без цены.
   - В потоковом YML-фиде (`PromFeedService`) пропускать оферы с `price <= 0` (по аналогии с Rozetka), предотвращая блокировку импорта каталога со стороны валидатора Prom.

2. **Честная классификация замечаний экспорта Prom.ua (`id: Продукт не найден`)**:
   - Разделять в статистике и логах:
     - Ошибки данных (некорректные поля, описания, цены);
     - Товары, ожидающие первичного импорта через YML-фид (`pending_feed_import` / `Продукт не найден`), так как REST API Prom не умеет создавать товары через JSON.
   - Формировать прозрачный итоговый отчёт для модального окна и Activity Feed тенанта.

3. **Соблюдение лимитов архитектуры (AGENTS.md)**:
   - Лимит файлов: `prom-export.processor.ts` ≤ 500 строк.
   - 100% покрытие unit-тестами изменений.
