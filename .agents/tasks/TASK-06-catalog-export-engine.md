# TASK-06: Движок очередей BullMQ (Dispatcher & Chunk Workers)

- **ID:** TASK-06
- **Эпик:** Очереди и Масштабируемость
- **Статус:** Done
- **Приоритет:** High
- **Исполнитель:** Queue & Sync Worker Agent

---

## 🎯 Цель
Построить архитектуру очередей на BullMQ для безопасного и надежного экспорта каталогов любого объема (10 000+ товаров) с защитой от переполнения памяти и превышения лимитов API маркетплейсов.

---

## 📝 Требования и шаги реализации
1. Подключить `@nestjs/bullmq` к сервису.
2. Создать очереди:
   - `catalog-export-queue`: экспорт полного каталога.
   - `stock-sync-queue`: регулярное обновление остатков и цен.
   - `orders-queue`: обработка входящих заказов.
3. Реализовать паттерн **Dispatcher-Worker**:
   - `ExportDispatcher`: разбивает 10k товаров на порции (чанги) по 100-200 SKU и создает дочерние задачи (`jobs`) с параметрами `{ tenantId, tcodRange }`.
   - `ExportChunkWorker`: обрабатывает конкретный чанк товаров, форматирует под целевую платформу и отправляет с соблюдением Rate Limit (например, 2 запроса в секунду).
4. Реализовать отслеживание прогресса:
   - Обновление статуса в BullMQ (`job.progress(percent)`).
   - API эндпоинт `GET /api/v1/sync/jobs/:jobId` для проверки статуса выполнения.
5. Настроить повторные попытки (retry policy: 3 попытки, exponential backoff).

---

## ✅ Критерии приемки
- [ ] Экспорт тестовой базы на 5 907 товаров разбивается на ~30 чанков и успешно отрабатывает без падения сервиса.
- [ ] Ошибки на одном товаре/чанке логируются, не прерывая выполнение остальных задач.
