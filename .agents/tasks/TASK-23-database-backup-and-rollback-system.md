# TASK-23: Система резервного копирования и отката БД Limansoft (Backup, Restore & Safety Prompt)

- **ID:** TASK-23
- **Эпик:** Data Safety & Disaster Recovery
- **Статус:** Done
- **Приоритет:** High
- **Исполнитель:** Backend & Data Architect

---

## 🎯 Цель
Разработать надежный модуль создания полных резервных копий базы данных **Limansoft (MariaDB)** с возможностью отката (восстановления) до последнего бэкапа в 1 клик, скачивания архива дампа, интеграцией предупреждающего шлюза перед опасными операциями синхронизации и **полной поддержкой двух языков (RU / UK)**.

---

## 🏗️ Архитектура и функциональные требования

### 1. Двухуровневая архитектура бэкапов (`BackupService`)
- **Режим 1: «Быстрый бэкап данных (без медиа) / Швидкий бекап даних (без медіа)» (Fast / Data-only — по умолчанию)**:
  - Включает таблицы: `name` (группы/категории), `name2` (товары, цены, артикулы), `name2ost` (остатки складов), `strihcod` (штрихкоды);
  - Исключает тяжелое поле `LONGBLOB` таблицы `namedesc`;
  - Размер архива: всего **5–15 МБ** (для 5 000–10 000 товаров);
  - Скорость создания: **1–2 секунды** (может безопасно создаваться автоматически перед опасным импортом без задержек).
- **Режим 2: «Полный архив (с фотографиями) / Повний архів (з фотографіями)» (Full / Complete)**:
  - Включает все таблицы, включая бинарные фотографии `namedesc.photo` ... `photo5`;
  - Размер архива: **500 МБ — 3 ГБ**;
  - Выполняется асинхронно через фоновую очередь BullMQ с потоковым сжатием и прогресс-баром;
- **Хранение архивов**: в изолированной директории `data/backups/:tenantId/`:
  - Формат имени: `backup_{tenantId}_{YYYY-MM-DD_HH-mm-ss}_{mode}.sql.gz`;
  - Метаданные: дата создания, режим (`fast` | `full`), размер файла, количество сохраненных SKU, контрольная сумма SHA256;
- **Ротация архивов**: автоматическое удаление бэкапов старше 30 дней (хранение до 10 последних копий).

### 2. Откат до резервной копии и защита Redis (Restore & Distributed Locking)
- **Распределенная блокировка (`lock:tenant:{tenantId}:busy`)**:
  - На время восстановления бэкапа (restore) устанавливается глобальный мьютекс в Redis;
  - Любые фоновые крон-синхронизации, выгрузки цен, импорты из Horoshop/WooCommerce автоматически блокируются, исключая повреждение данных (Data Corruption) и Race Condition;
- **Эндпоинт `POST /api/v1/liman/:tenantId/backups/:filename/restore`**:
  - Восстановление структуры и данных из выбранного gzip-дампа в транзакционном режиме;
  - Двойной защитный барьер: требование подтверждения в UI (*«Текущее состояние базы будет перезаписано / Поточний стан бази буде перезаписано даними за {Дата}»*);
  - Логирование операции восстановления в глобальный аудит безопасности.

### 3. REST API эндпоинты модуля
- `POST /api/v1/liman/:tenantId/backups` — создать резервную копию (тело: `{ mode?: 'fast' | 'full' }`);
- `GET /api/v1/liman/:tenantId/backups` — получить список доступных копий с размерами, режимом (`fast`/`full`) и датами;
- `GET /api/v1/liman/:tenantId/backups/:filename/download` — скачать архив `.sql.gz` на компьютер;
- `POST /api/v1/liman/:tenantId/backups/:filename/restore` — восстановить базу из архива с Redis-блокировкой;
- `DELETE /api/v1/liman/:tenantId/backups/:filename` — удалить резервную копию.

### 4. Интеграция с мастерами обратной синхронизации (Pre-Sync Safety Prompt)
- При открытии модального окна опасных операций (TASK-22 импорт из Хорошоп с перезаписью или TASK-17 импорт из WooCommerce):
  - **Предупреждающий блок на выбранном языке (RU/UK)**:
    > 🛡️ **Рекомендация безопасности: / Рекомендація безпеки:** Перед началом перезаписи каталога настоятельно рекомендуется создать резервную копию учетной базы Limansoft.
  - Индикатор последнего бэкапа:
    - `🟢 Последний бэкап: Сегодня в 08:30 (18.4 МБ) / Останній бекап: Сьогодні о 08:30 (18.4 МБ)` — если бэкап свежий;
    - `🟡 Внимание: Последний бэкап создавался более 3 дней назад / Увага: Останній бекап створювався більше 3 днів тому` или `🔴 Бэкапы отсутствуют! / Бекапи відсутні!`.
  - Опция по умолчанию включена:
    `[x] Автоматически создать резервную копию перед запуском / Автоматично створити резервну копію перед запуском синхронізації`.

### 5. Пользовательский интерфейс и мультиязычность (RU / UK)
- Раздел **«Резервные копии / Резервні копії (Backups)»**:
  - Кнопка **«💾 Создать резервную копию сейчас / Створити резервну копію зараз»**;
  - Таблица архивов: Имя файла, Дата создания, Размер, Кнопки: *«Восстановить (Откат) / Відновити (Откат)»*, *«Скачать файл / Завантажити файл»*, *«Удалить / Видалити»*.
  - Все системные сообщения, подтверждения и предупреждения полностью локализованы на Русский и Украинский языки.

### 6. Тестирование модуля (Backend Jest + Frontend Vitest)
- **Бэкенд тесты (Jest)**:
  - Unit-тесты для `BackupService`:
    - Проверка генерации дампа в быстром режиме `fast` (сохраняет только таблицы `name`, `name2`, `name2ost`, `strihcod`, проверяет целостность gzip);
    - Проверка генерации дампа в полном режиме `full` (включает `namedesc`);
    - Проверка парсинга и валидации архива перед восстановлением;
    - Проверка восстановления базы (`restore`) в транзакции;
    - Проверка захвата и освобождения распределенной блокировки Redis `lock:tenant:{tenantId}:busy` (отклонение повторных операций `409 Conflict`);
    - Проверка ротации старых файлов бэкапа (>30 дней / лимит 10 штук).
- **Фронтенд тесты (Vitest + RTL)**:
  - Компонентные тесты таблицы резервных копий и кнопок действий;
  - Проверка диалогового окна подтверждения отката (защита от случайного клика).
