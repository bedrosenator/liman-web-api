## 🎯 Цель
Разработать центральную панель управления главного администратора (`/superadmin`) с **единой сводной матрицей настроек всех клиентов в одном окне** (без необходимости переключаться между магазинами), безопасным маскированием паролей, управлением базой SQLite (`data/liman_master.sqlite`), тестированием баз MariaDB Limansoft, генерацией клиентских ссылок, мониторингом очередей BullMQ и **полной поддержкой двух языков (RU / UK)**.

---

## 🏗️ Архитектура и функциональные требования

### 1. Сводная матрица настроек всех клиентов (All-Tenants Master Grid)
Главный инструмент администратора — единая интерактивная таблица, где по каждой строке видна вся конфигурация магазина:
- **Колонка 1: Магазин / Тенант**: ID (`columb`), Название, статус активности (`Active`/`Inactive`), дата последнего обмена.
- **Колонка 2: БД Limansoft (MariaDB)**: `Host:Port/DBName`, выбранная колонка цены (`cena2`), колонка склада (`skl_k`), индикатор связи (с кнопкой быстрого пинга).
- **Колонка 3: Хорошоп**: Домен магазина (`shop724088.horoshop.ua`), логин, статус автосинхронизации (Вкл/Выкл, интервал), бейдж связи.
- **Колонка 4: Prom.ua**: Наличие API-ключа, статус экспорта, интервал.
- **Колонка 5: Rozetka**: Client ID, статус выгрузки прайса.
- **Колонка 6: WooCommerce**: URL сайта, статус Two-Way Sync.
- **Колонка 7: Действия администратора**:
  - **«Редактировать / Редагувати»** (быстрое модальное окно изменения любых параметров);
  - **«Войти как клиент / Увійти як клієнт» (Open Portal)** — мгновенный переход в изолированный кабинет этого магазина;
  - **«Ссылка клиента / Посилання клієнта»** — копирование персональной ссылки для отправки владельцу;
  - **«Ротация ключа / Ротація ключа»**.

### 2. Защита от подглядывания и утечек: Маскирование паролей (Sensitive Data Masking & API Security)
- **Защита в REST API**: Основной эндпоинт списка `GET /api/v1/admin/tenants` возвращает все чувствительные данные (`dbPassword`, `horoshopPassword`, `promApiKey`, `rozetkaSecret`, `apiKey`) в виде маскированных строк `••••••••`. Это защищает от утечки паролей десятков клиентов через вкладку Network DevTools при демонстрации экрана или аудите.
- **Безопасное раскрытие (Reveal on Demand)**:
  - При явном клике супер-админа на иконку `👁 (Показать/Скрыть)` отправляется целевой запрос `POST /api/v1/admin/tenants/:id/reveal-credentials` для получения реального секрета только по выбранному магазину.
  - Операция раскрытия фиксируется в логах безопасности (`audit.log`).

### 3. Сводные метрики системы (SaaS Overview)
- Карточки статистики в шапке дашборда:
  - Количество активных клиентов (тенантов);
  - Суммарное количество товаров в синхронизации;
  - Статус Redis и очередей BullMQ (🟢 Normal / 🟡 Busy / 🔴 Error);
  - Общий объем завершенных синхронизаций за последние 24 часа.

### 4. Модальное окно создания и настройки клиента
- Форма добавления (`POST /api/v1/tenants`) и редактирования (`PATCH /api/v1/tenants/:id`):
  - **Общие данные**: ID (slug, только латиница), Название магазина, флаг активности;
  - **База данных Limansoft (MariaDB)**: Host (`127.0.0.1`), Port (`3306`), DB Name (`columbDB`), User, Password;
  - **Кнопка «Тест соединения с MariaDB / Тест підключення до MariaDB»**: вызывает `GET /api/v1/liman/:tenantId/ping` прямо из модалки с выводом времени отклика (мс) и количества доступных SKU;
  - **Маппинг колонок учета**: Прайс-колонка (`cena2`, `cena3`...) и колонка склада (`skl_k`, `skl_r`...).

### 5. Монитор очередей BullMQ
- Отображение текущего состояния фоновых очередей:
  - `sync-stock` (обновление цен и остатков);
  - `export-catalog` (пакетный экспорт каталогов);
  - `import-woo-catalog` (импорт из WooCommerce);
  - `import-horoshop-catalog` (обратный импорт из Хорошоп).
- Счётчики задач: `waiting`, `active`, `completed`, `failed`.
- Кнопка принудительного повтора упавших задач (`retry failed`).

### 6. Мультиязычность интерфейса (i18n: RU / UK)
- Все заголовки колонок, карточки метрик, плейсхолдеры форм, кнопки действий, системные статусы и toast-уведомления используют словарь переводов `LanguageContext` с мгновенным переключением `RU ↔ UK`.

### 7. Тестирование модуля (Backend Jest + Frontend Vitest)
- **Бэкенд тесты (Jest)**:
  - Unit-тесты контроллера `AdminTenantsController`:
    - Проверка маскирования паролей (`••••••••`) в эндпоинте списка клиентов;
    - Проверка эндпоинта раскрытия `POST /reveal-credentials` и записи в аудит;
    - Проверка CRUD-операций тенантов в SQLite;
    - Тест проверки соединения с MariaDB (`GET /ping`);
- **Фронтенд тесты (Vitest + RTL)**:
  - Рендеринг сводной таблицы `AllTenantsMasterGrid`;
  - Проверка клика по иконке `👁` и вызова API раскрытия;
  - Валидация модального окна добавления/редактирования клиента.
