# TASK-22: Обратная синхронизация каталога из Хорошоп в учетную БД Limansoft (MariaDB)

- **ID:** TASK-22
- **Эпик:** Horoshop Интеграция & Двусторонняя синхронизация
- **Статус:** Backlog
- **Приоритет:** High
- **Исполнитель:** Backend & Integration Architect

---

## 🎯 Цель
Разработать надежный, безопасный и масштабируемый механизм обратной выгрузки каталога товаров из магазина **Хорошоп** в учетную базу данных **Limansoft** (MariaDB: `name2`, `name2ost`, `namedesc`, `strihcod`) с поддержкой фоновой очереди BullMQ, защитой от Race Condition через **распределенные блокировки Redis**, защитой от лимитов Хорошоп API (**Throttling & Batching**), гранулярными режимами синхронизации (только новинки vs полная перезапись), модальным окном подтверждения рисков и **полной поддержкой двух языков (RU / UK)**.

---

## 🏗️ Архитектура и функциональные требования

### 1. Защита от Race Condition (Распределенные блокировки Redis)
- Перед стартом импорта в Redis устанавливается атомарный мьютекс `lock:tenant:{tenantId}:sync` с TTL.
- Любые параллельные операции (периодический крон-обновлятор остатков, восстановление бэкапа или импорт из других каналов) проверяют наличие блокировки:
  - При наличии активного лока фоновые задачи пропускают итерацию и логируют: `⏭️ [tenantId] Пропуск крона: выполняется импорт каталога Хорошоп`.
- Лок гарантированно освобождается в блоке `finally` после завершения или ошибки задачи.

### 2. Защита от лимитов Horoshop API (Rate Limiting & Throttling)
- Выкачка товаров батчами по 50–100 SKU с паузой (throttle delay) 200–300 мс между запросами для предотвращения HTTP 429 Too Many Requests.
- Скачивание фото: пул воркеров с параллелизмом не более 5 одновременных потоков.
- Экспоненциальный повтор (Exponential Backoff): при получении 429 или 503 от Хорошоп задача делает паузу 3с → 6с → 12с перед повторной попыткой.

### 3. Режимы синхронизации (Sync Modes)

#### Режим А: «Только новые товары / Тільки нові товари» (Safe Mode — по умолчанию)
- Сопоставление по артикулу (`article`) или штрихкоду (`barcode`/`gtin`);
- Если товар уже найден в `name2` или `strihcod` — он **пропускается (`skipped`)**;
- Если товара в базе Limansoft нет:
  - Выделяется уникальный код `tcod = MAX(tcod) + 1`;
  - Создается мастер-запись в `name2` (название, категория, розничная цена);
  - Скачиваются фотографии по URL из Хорошопа и сохраняются в BLOB таблицы `namedesc`;
  - Записывается начальный остаток в `name2ost.skl_k`;
- **Безопасность**: 100% защита от случайного изменения существующих учетных цен и складских остатков в Limansoft.

#### Режим Б: «Полное обновление (Перезапись и обновление существующих) / Повне оновлення (Перезапис та оновлення існуючих)» (Overwrite Mode)
- Для существующих товаров: обновляются наименование, описание, цена, остаток и медиа в соответствии с сайтом Хорошоп;
- Для отсутствующих товаров: создаются новые позиции с выделением `tcod`;
- **Защитный барьер (Safety Confirmation Modal)**:
  - Предупреждающее модальное окно с ярким сигналом опасности на выбранном языке (RU/UK):
    > ⚠️ **Внимание! / Увага!** Вы выбрали режим перезаписи. Данные цен и складских остатков в учетной системе Limansoft будут заменены данными с сайта Хорошоп. Это действие невозможно отменить.
  - Обязательный чекбокс: *«Я осознаю риск замены цен и остатков в учетной базе / Я усвідомлюю ризик заміни цін та залишків в обліковій базі»* для разблокировки кнопки запуска.

### 4. Гранулярные фильтры синхронизации
Пользователь может тонко настроить, какие именно поля обновлять:
- `[x] Обновлять розничную цену / Оновлювати роздрібну ціну (cena2)`
- `[x] Обновлять складской остаток / Оновлювати складський залишок (skl_k)`
- `[x] Загружать и обновлять фотографии / Завантажувати та оновлювати фотографії (namedesc)`
- `[x] Создавать новые категории товара / Створювати нові категорії товару (таблиця name / groups)`
- `[ ] Обновлять только товары в наличии / Оновлювати тільки товари в наявності (presence = true)`

### 5. Интеграция с системой бэкапа (Pre-Sync Safety Backup)
- Опция `[x] Создать резервную копию перед запуском (Рекомендуется) / Створити резервну копію перед запуском (Рекомендовано)` (включена по умолчанию):
  - При запуске импорта первым шагом автоматически вызывается быстрый бэкап данных (`BackupService.createBackup(tenantId, { mode: 'fast' })`);
  - В лог задачи пишется ID и имя созданного дампа (`backup_columb_2026-09-16_09-00-00_fast.sql.gz`);
  - В случае аварии или непредвиденного сбоя пользователь может мгновенно откатить базу в 1 клик через модуль TASK-23.

### 6. Серверная архитектура в `liman-web-api`
- **Очередь BullMQ (`import-horoshop-catalog`)**:
  - Асинхронная обработка для каталогов любого размера (10 000+ SKU) без таймаутов браузера;
  - Постраничная выкачка товаров через `POST /api/catalog/export/`;
  - Потоковое обновление прогресса задачи: `job.updateProgress(percent)`;
  - Отслеживание через стандартный эндпоинт `GET /api/v1/sync/jobs/import-horoshop-catalog/:jobId`.
- **API Контроллер (`HoroshopSyncController`)**:
  - `POST /api/v1/horoshop/:tenantId/import/catalog`:
    - Принимает тело: `{ mode: 'only_new' | 'overwrite', updatePrices?: boolean, updateStock?: boolean, updateImages?: boolean, createBackup?: boolean }`;
    - Возвращает `202 Accepted` и `jobId`.

### 6. Пользовательский интерфейс и мультиязычность (RU / UK)
- Карточка **«Импорт товаров из Хорошоп в Limansoft / Імпорт товарів з Хорошоп до Limansoft»**:
  - Выбор режима переключателем с подсказками;
  - Кнопка **«Начать импорт каталога / Почати імпорт каталогу»**;
  - Модальное окно с предупреждением при выборе режима перезаписи;
  - Прогресс-бар в реальном времени с выводом счетчиков: *Обработано: 1 240 / 5 768 (Создано: 45, Обновлено: 1 195, Ошибок: 0)*;
  - Итоговый детальный отчет по завершении.
  - Все надписи, чекбоксы и текст модалки предупреждения локализованы на Русский и Украинский языки.
