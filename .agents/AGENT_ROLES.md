# 🤖 Регламент взаимодействия AI-агентов (Agent Collaboration Framework)

Данный документ описывает протокол совместной работы автономных AI-агентов над проектом **liman-web-api**.

---

## 🎭 Роли Агентов

### 1. 🏗️ Lead Architect Agent (Архитектор)
- **Зона ответственности:**
  - Проектирование контрактов API, DTO, схем данных и модульной архитектуры NestJS.
  - Декомпозиция задач, ведение `task-board.md` и синхронизация с Trello.
  - Контроль соблюдения архитектурных границ (Clean Architecture / Hexagonal).

### 2. 💾 Database & Core Agent (Бэкенд-инженер)
- **Зона ответственности:**
  - Реализация доступа к данным Limansoft MariaDB (`mysql2` / Knex / TypeORM).
  - Управление пулами подключений для мультиарендности (`TenantConnectionManager`).
  - Разработка SQLite хранилища конфигураций тенантов.
  - Модуль потоковой отдачи картинок (`MediaModule`) из BLOB `namedesc`.

### 3. ⚡ Queue & Sync Worker Agent (Инженер очередей)
- **Зона ответственности:**
  - Настройка Redis и BullMQ очередей (`export-catalog`, `sync-stock`, `import-orders`).
  - Реализация Dispatcher / Worker чанков для батчинга по 100-200 товаров.
  - Механизмы Retry, Rate Limiting, Dead Letter Queue (DLQ).
  - Стриминг и сбор метрик прогресса задач (0-100%).

### 4. 🔌 Integration Adapter Agent (Инженер интеграций)
- **Зона ответственности:**
  - Реализация SDK и клиентов для Prom.ua, Rozetka, WooCommerce, Horoshop.
  - Генератор YML/XML фидов с экранированием и потоковым формированием.
  - Маппинг категорий и атрибутов между системами.

### 5. 🛡️ QA & Security Agent (Тестировщик и ИБ)
- **Зона ответственности:**
  - Настройка API Key аутентификации и JWT для панели управления.
  - Валидация входных данных (`class-validator`, `Zod`).
  - Unit и e2e тесты (`jest`).
  - Swagger/OpenAPI спецификация (`@nestjs/swagger`).

## 🔄 Протокол выполнения задачи (Lifecycle)

1. **Взятие задачи:**
   - Агент переносит задачу в `.agents/task-board.md` из `To Do` в `In Progress`.
   - В файле `.agents/tasks/TASK-XX.md` фиксируется текущий статус и исполнитель.
2. **Разработка:**
   - Код пишется в строгом соответствии с [Clean Code & Engineering Standards](file:///Users/bedrosenator/Work/liman-web-api/.agents/rules/clean-code.md).
   - Строгое соблюдение **SOLID, DRY, KISS**:
     - Запрет нумерованных переменных-копипастов (`p1`, `p2`, ...).
     - Единая точка синхронизации зависимых таблиц (никакого дублирования между ветками INSERT/UPDATE).
     - Декомпозиция функций по принципу единой ответственности (SRP) и единого уровня абстракции (SLAP).
     - Искоренение магических чисел и строк через константы предметной области (`LIMAN_LIMITS`).
     - Строгие транзакционные границы (`BEGIN / COMMIT / ROLLBACK`) с гарантированным освобождением ресурсов в `finally`.
   - Все изменения документируются в Swagger аннотациях.
3. **Верификация:**
   - Запуск локальных тестов: `npm test` (100% успех всех тестовых наборов).
   - Проверка компиляции: `npm run build` (0 ошибок).
   - Задача переносится в `In Review / QA`.
4. **Завершение:**
   - После успешного прохождения проверок задача переносится в `Done`.
   - Обновляется статус в Trello через скрипт синхронизации.
